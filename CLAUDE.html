CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

⚠️ 對話開始時必須執行

每次對話開始，立即依序讀取以下檔案，再回應任何問題：

  1. .kiro/steering/basic.md — 設計哲學、測試標準、執行控管、Docker 與 Windows 指令規範
  2. .kiro/steering/tech.md — 技術棧、建置指令、API 端點
  3. .kiro/steering/structure.md — 專案目錄結構、多租戶設計
  4. .kiro/steering/product.md — 產品功能、系統角色、使用者流程

以上為 source of truth，所有規範以 .kiro/steering/ 為準。

⚠️ 新功能開發：Spec-First 強制流程（Strict）

收到任何新功能需求，禁止直接寫程式碼。必須依序完成以下三步驟，每步驟必須等待使用者確認後才進行下一步。

流程

步驟 產出檔案 中斷點
Step 1 specs/{feature}/requirements.md ⛔ 等待使用者確認
Step 2 specs/{feature}/design.md ⛔ 等待使用者確認
Step 3 specs/{feature}/tasks.md 逐項完成，勾選 [x]

強制規則

  1. ❌ 禁止跳步：未完成 requirements.md 不得建立 design.md，未完成 design.md 不得建立 tasks.md
  2. ❌ 禁止口頭設計：所有設計必須寫入檔案，禁止在對話中口頭描述而不建檔
  3. ❌ 禁止直接寫程式碼：未完成三份 spec 文件前，不得建立任何 Controller、Model、Migration、前端元件
  4. ✅ 等待確認：Step 1 與 Step 2 完成後，必須明確詢問使用者「是否確認？」，收到確認後才進行下一步

Spec 資料夾結構

specs/
└── {feature-name}/
    ├── requirements.md   # Step 1：需求定義
    ├── design.md         # Step 2：技術設計
    └── tasks.md          # Step 3：實作任務清單

文件格式

requirements.md

# 需求：{功能名稱}

## 使用者故事
- 身為 {角色}，我希望 {動作}，以便 {目的}

## 驗收條件
- [ ] 條件 1
- [ ] 條件 2

## 範圍外（Out of Scope）
- 排除項目

design.md

# 技術設計：{功能名稱}

## 資料模型
- 新增/修改的資料表與欄位

## API 設計
- Endpoint、Method、Request/Response 結構

## 前端元件
- 頁面與元件清單

## 影響範圍
- 修改到的既有檔案

tasks.md

# 實作任務：{功能名稱}

## 任務清單
- [ ] 1. Migration：建立 xxx 資料表
- [ ] 2. Model：建立 Xxx Model
- [ ] 3. Controller：建立 XxxController
- [ ] 4. API Routes：註冊路由
- [ ] 5. 前端頁面：建立 XxxPage.tsx
- [ ] 6. 測試：撰寫 Feature Test

快速參考

開發環境啟動（Docker Compose）

所有開發在容器內進行，無需本地安裝 PHP、Node.js、Composer 等。

# 1. 啟動所有服務
docker compose up -d

# 2. 查看服務狀態
docker compose ps

# 3. 查看服務日誌
docker compose logs -f laravel        # 後端 API
docker compose logs -f react-admin     # 系統管理後台
docker compose logs -f react-frontend  # 企業用戶應用
docker compose logs -f mysql           # 資料庫

後端 API（Laravel）

# 在容器內執行
docker compose exec laravel composer install      # 安裝依賴
docker compose exec laravel php artisan migrate   # 執行遷移
docker compose exec laravel php artisan test      # 執行測試
docker compose exec laravel php artisan test tests/Feature/Admin/OrganizationControllerTest.php  # 特定測試
docker compose exec laravel php artisan cache:clear && php artisan config:clear  # 清除快取

# API 訪問
curl http://localhost:8000/api/admin
curl http://localhost:8000/api/org

前端 - 系統 OWNER 管理後台（React Admin）

# 在容器內執行
docker compose exec react-admin npm install       # 安裝依賴
docker compose exec react-admin npm run dev       # 開發伺服器
docker compose exec react-admin npm run build     # 編譯打包
docker compose exec react-admin npm run test:unit # 執行單元測試
docker compose exec react-admin npm run type-check  # 型別檢查
docker compose exec react-admin npm run lint      # 程式碼檢查
docker compose exec react-admin npm run format    # 程式碼格式化

# 訪問應用
open http://localhost:5173

前端 - 企業用戶應用（React Frontend）

# 在容器內執行
docker compose exec react-frontend npm install       # 安裝依賴
docker compose exec react-frontend npm run dev       # 開發伺服器
docker compose exec react-frontend npm run build     # 編譯打包
docker compose exec react-frontend npm run test:unit # 執行單元測試
docker compose exec react-frontend npm run type-check  # 型別檢查
docker compose exec react-frontend npm run lint      # 程式碼檢查
docker compose exec react-frontend npm run format    # 程式碼格式化

# 訪問應用
open http://localhost:5174

資料庫（MySQL）

# 在 MySQL 容器內執行
docker compose exec mysql mysql -u ezsport -pezsport ezsport

# 常用指令
SHOW TABLES;
DESCRIBE organizations;
SELECT * FROM organizations;

容器操作

# 停止所有服務（保留資料）
docker compose stop

# 重啟單一服務
docker compose restart laravel
docker compose restart react-admin
docker compose restart react-frontend

# 查看容器資源使用
docker compose stats

# 清理（⚠️ 謹慎使用，會刪除容器但保留 volumes）
docker compose down

⚠️ 禁止操作：docker compose down 除非必須重建環境且已獲同意。詳見 .kiro/steering/basic.md Section 4.2。

注意事項

檔案用途

  • 本檔案用於 Claude Code（claude.ai/code）的開發指導
  • Kiro IDE 使用 .kiro/steering/ 目錄下的 steering 檔案（Kiro 有內建 Spec 機制）
  • 兩個開發環境共用 .kiro/steering/ 作為 source of truth

開發環境

  • 開發環境：Docker Compose（推薦）
  • 本地開發：不需要本地安裝 PHP、Node.js、Composer、npm 等工具
  • 所有指令：在容器內執行，使用 docker compose exec 前綴

規範與約束

  • 遵循 .kiro/steering/basic.md 的設計哲學、測試標準、執行控管
  • 遵循 .kiro/steering/tech.md 的技術棧與 API 設計規範
  • 禁止行為詳見 .kiro/steering/basic.md Section 3-4

進度同步

  • 完成 Spec 文件時，必須更新 .kiro/steering/dash.md
  • 完成 API 端點時，必須更新 .kiro/steering/tech.md 的「主要 API 端點」區塊
  • 詳見 .kiro/steering/basic.md Section 4.3
